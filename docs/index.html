What it is, measured

A deterministic filter for AI-made errors in research claims. Blind run, engine frozen at the sealed tag: 53 of 82 bad claims stopped, 51 of 63 good claims not rejected.

Corpus: 233 research claims written by AI sessions under human governance in a sister project’s repository. 50 were excluded as contaminated because the coder could see the outcome; 183 were scored. Each claim carries the file and commit where it was asserted. A separate session coded the claims blind. The engine was frozen at a git tag before coding and the verdicts were sealed by hash before the outcomes were opened. No language model in the verdict. Outcomes are the project’s own later corrections, not an external oracle. n is small and the intervals reflect it.

  • Not a fraud detector, and we measured it: on 888 clean papers vs 6,348 retracted ones, recomputable numeric inconsistencies did not separate the groups. CAPAS checks the structure of evidence; a consistent fabrication passes (the GIGO ceiling).
  • The gate reads the claim text only through a fixed list of patterns, and those patterns can only lower a verdict. It decides on declared fields. What is not declared ends in HOLD or REWRITE, never in ACCEPT.
  • Rules added after a failure make the sealed claims training data. Each false-accept becomes a required field and a regression test. The figures above belong to the engine frozen at the sealed tag. A re-score with a later engine is in-sample and is never published as the blind rate. A new rule earns credit only on the next sealed batch; until then the blind rate of the current engine is unknown.

A third party can re-derive these figures from the public files: sealed verdicts, outcome labels and evidence fields in research/ginibre_corpus/public. Each claim text is published as a sha256 hash only, because the paper is unpublished. Replayed with the engine at each frozen tag (ginibre-ciego-v1 to v6), the redacted payloads reproduce 232 of 233 sealed verdicts. Not checkable by a third party: the sealing times and the tag dates, which the author recorded. The full ledger, the limits and what is not validated: CAPAS in depth →

Where it Lives

Four-step workflow

From claim draft to admissibility decision in one deterministic pass.

01
Claim drift
A paper reports association. A dataset row records causation. CAPAS enforces the boundary when the claim is declared as a causal claim type or uses a phrase on its fixed pattern list.
02
Select mode
Guided builder, raw JSON, batch evaluation, or claim-candidate extraction (deterministic preview, human confirmation).
03
Run gate
Schema v3 and claim-type rules return ACCEPT, REWRITE, REJECT, or HOLD with full provenance.
04
Inspect decision
Review the verdict, schema errors and provenance blockers; complete the evidence fields.
Verdict Reference

Four possible outcomes

Every gate run returns exactly one of these. Each carries a machine-readable reason trail.

ACCEPT

Claim is admissible

All schema constraints pass. The declared evidence licenses a statement generated from the declared fields; the original sentence is never carried. No licensing or reproducibility blockers.

p_value=0.03, alpha=0.05
effect_direction_confirmed: true
→ ACCEPT · audit_hash ff23bfcc
REWRITE

Claim needs adjustment

Evidence is present but the claim overreaches. Direction, scope, or causal language must be corrected before resubmission.

p_value=0.03, alpha=0.05
effect_direction_confirmed: false
→ REWRITE · audit_hash 2a2c5234
REJECT

Claim is inadmissible

Critical evidence is missing, contradicted, or irreproducible. The claim cannot be licensed in its current form.

artifact_available: false
independent_reproduction_pass: false
→ REJECT · audit_hash 1cc473f8
HOLD

Pending verification

Evidence is incomplete or no external oracle is available; the gate returns HOLD.

p_value=0.03, alpha=0.05
effect_direction_confirmed: (missing)
→ HOLD · audit_hash 9033f4c1
Why CAPAS

Structured admissibility gating for scientific claims

Each verdict re-derives to the same audit hash on any machine; no model score is involved.

What CAPAS is NOT

Not a fact-checker. CAPAS validates evidence licensing and schema compliance, not truth.

Not a plagiarism detector. CAPAS checks admissibility, not citation matching.

Not an LLM wrapper. The decision path makes no language model calls.

Not a replacement for peer review. CAPAS runs before editorial judgment, not instead of it.

What CAPAS IS

A deterministic claim admissibility gate. The same input produces the same output.

A schema enforcement layer. CAPAS Schema v3 defines a valid evidence package.

A provenance audit tool. Every blocker is machine-readable and exportable.

An API for research pipelines, publishing workflows and audit systems.

Audit output

Every decision is an audit artifact

CAPAS produces an auditable evidence trail for each decision. Every verdict carries an action: ACCEPT licenses reuse · REWRITE returns the corrected claim with an Original→Licensed diff · REJECT names the missing evidence fields · HOLD lists the obligations to resolve before reuse.
