Krenn·IQ (Atlas & CAPAS) · Version 1.0 · Effective 2026-06-24 · Operator: Fco. Osvaldo Morales Vilchis
Summary. The engine is open source under Apache 2.0 and runs on your own hardware. Circuits submitted to the hosted web are processed in memory and are not stored, not shared and never used to train any model. Atlas returns a compute-cost triage: a decision-support diagnostic, not a proof. For sensitive or classified work, run the local engine.

1Terms of Service

1.1 What the service is

Krenn·IQ provides two tools, Atlas (quantum compute-cost triage) and CAPAS (claim-admissibility gate), as a hosted web application and as a downloadable open-source engine. The open-source components are licensed under the Apache License 2.0; see the LICENSE and NOTICE files in each repository.

1.2 Scope and limits

Atlas produces an operational diagnostic: an estimate of the classical-simulation cost of a circuit and a recommended compute route, with calibrated confidence. It is not a proof of classical simulability or quantum advantage, nor financial or investment advice. Reduced-confidence verdicts are flagged. Decisions made with the tool, including spending on quantum hardware, remain the user’s responsibility.

1.3 Acceptable use

The hosted web is for evaluation and individual use, subject to fair-use rate limits that may change. Disrupting the service, circumventing rate limits at scale or scraping the API to reconstruct the engine is not permitted. Production or integrated use requires the downloadable engine or an Enterprise agreement.

1.4 Warranty & liability

The operator is not liable for any direct or indirect damages, losses or decisions arising from use of the tool. 2Privacy Policy

2.1 Data collected

The hosted web operates without user accounts and requires no personal data to run an analysis. A submitted circuit (OpenQASM) is processed in memory and the result returned. Transient web-server metadata, such as the IP address used for rate limiting and abuse prevention, is not used to build user profiles.

2.2 Exclusions

  • Submitted circuits are not stored after the request completes.
  • Circuits, inputs and results are not used to train any model.
  • Data is not sold or shared with third parties.

2.3 Third-party processing, optional features

Optional features, such as natural-language interpretation in the Sponsor tier, send the structured numeric outputs of the engine to a third-party LLM provider (Anthropic). The feature is opt-in and indicated in the UI before it runs; the free and local tier makes no external calls. The downloadable engine makes no external calls except an optional, documented license and calibration check.

2.4 Contact

Privacy questions: fomv9354@gmail.com.

3Data Policy

3.1 Ownership of circuits

Every submitted circuit is treated as confidential intellectual property. The hosted service processes it ephemerally, in memory for the duration of the request, and does not persist it to disk or any database.

Certificates issued through the authenticated /api/certificate endpoint are stored on the server’s disk with the submitted claim, evidence and verdict, so they can be retrieved and verified by id. They are not used to train any model. Ask for deletion through the contact on this page.

3.2 On-premise and air-gapped deployment

For defense, pharmaceutical, financial or any work where circuits cannot leave the network, use the downloadable engine: it runs on your hardware, makes no analysis calls to Krenn·IQ servers, and circuits never transit the public internet. This is the recommended mode for data-residency and classified workloads.

3.3 Hosting & jurisdiction

The hosted demo runs on cloud infrastructure in the United States (Azure, East US) and is intended for evaluation. Data-residency requirements, such as EU/GDPR or in-country mandates, are met with the local engine or a regional or on-premise Enterprise deployment on request.

3.4 Hardware-calibration data

Atlas is calibrated against measurements on publicly accessible quantum hardware. Those calibration datasets are part of the product; submitted circuits are never added to them.

4CAPAS data handling, by endpoint

This section describes the current CAPAS deployment. It is not legal advice.

  • Gate App in the browser. The decision log is stored only in the browser’s localStorage. Nothing is sent to the server unless Run is pressed.
  • POST /api/decide and POST /api/gate. The payload is processed in memory to compute the verdict. It is not written to disk and not used for training. Host: Azure Container Apps, East US.
  • POST /api/certificate. Requires the API key. The certificate, with claim, evidence and verdict, is written to the server’s disk so it can be retrieved by id. It is retained until deletion is requested through the contact on this page.
  • Library, MCP server and CLI. They run on the user’s machine. They make no network call unless CAPAS_VERIFY_REMOTE_SOURCES=1 is set and source_urls are declared.
